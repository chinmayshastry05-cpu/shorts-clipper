# Verification — Shorts Clipper v0.2.1

Bugfix release for three bugs reported from real use on the Learn AI channel.

## Fixes

1. **`--caption-script hinglish` silently no-opped in the v0.2.0 AppImage.**
   `indic-transliteration` was missing from requirements.txt, and
   `to_hinglish()` swallowed the ImportError and returned Devanagari.
   Now: the dep is in requirements.txt (bundled in the AppImage), and a
   Hinglish render without it raises `HinglishUnavailableError` with an
   install hint instead of shipping the wrong script.

2. **IAST romanizer mangled English loanwords.** "टू डू हियर इज़" came out
   "tu du hiyar ij", "करियर एडवाइज़र" came out "edavaaijara". New
   `hinglish.py`: a ~250-entry Devanagari->English loanword lexicon
   (function words + career/tech/money/media vocabulary, nukta variants,
   स/ज़ plural suffixes) checked before the phonetic pass; the phonetic
   pass keeps natural Hinglish spelling ("कैसे" -> "kaise"). Latin-script
   source words pass through untouched.

3. **Static face anchor broke on two-shot cuts.** The crop held one anchor
   for the whole segment, so a cut to a second speaker left them cropped
   out. New `detect_face_track()` samples faces over time, splits anchor
   runs at jumps > 15% of frame width, merges sub-1.5s runs, and the
   renderer (`export.render_tracked`) trims/crops/concats per run in one
   ffmpeg pass. A persistent two-face layout logs and surfaces a
   "second speaker may be cropped" warning (`two_shot` in the CLI JSON).

Also: `--keep-ass` CLI flag (keeps the generated .ass next to the output).

## Tested

- 39 unit tests pass (16 new: lexicon, phonetic romanization, loud
  missing-dep failure in both `to_hinglish` and `write_ass`, run splitting/
  merging/coalescing, two-shot detection, tracked filtergraph structure).
- AppImage rebuilt from this tree: `indic_transliteration` 2.3.82 and
  `hinglish.py` verified inside the artifact.
- End-to-end AppImage run on a real Hinglish clip (edge-tts hi-IN voice,
  loanword-heavy script): transcript (lang=hi), render 1080x1920, zero
  Devanagari left in the .ass, burned captions visually verified
  (romanized, cinematic pop, correct position).
- `render_tracked` smoke-tested with ffmpeg on a synthetic two-anchor
  video: correct per-run crop windows, audio preserved.
- Loanword path verified inside the AppImage python:
  "टू डू हियर इज़ करियर एडवाइज़र" -> "to do here is career advisor".

## Not tested

- Two-shot re-anchoring on a real interview video (synthetic only) — no
  suitable real two-shot footage on hand; the Haar cascade needs real faces.
- YouTube-URL inputs from this build host (datacenter IPs are often
  blocked); the audio-whisper fallback path is what ran here.
- GUI (headless test host): the phone preview still shows the single
  dominant anchor, not the per-run track.
