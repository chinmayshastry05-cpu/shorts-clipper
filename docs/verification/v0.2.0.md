# Verification — Shorts Clipper v0.2.0

v0.2.0 changes: (1) all branding renamed "ShortCut Linux" -> "Shorts Clipper"
(package `shortscut` -> `shortsclipper`, AppImage `ShortsClipper-x86_64.AppImage`),
(2) face-anchored 9:16 crop (OpenCV Haar cascade, median of 8 sampled frames,
center-crop fallback) replacing the v0.1 fixed center crop, with a
`--no-face-track` CLI escape hatch.

Test media: `Bernie_Brief_Income_Inequality_Ep_1.mp4` (archive.org item
`berniebriefincomeinequalityep1`, 517 s, 1920x1080, single on-camera speaker),
trimmed to 150 s for test speed. Variants built with ffmpeg:
- `padded.mp4` — padded to 2880x1080 so the speaker sits at 33% of frame width
  (a v0.1 center crop cuts him out of frame entirely)
- `faceless.mp4` — cropped to the bottom 1920x540 (torso/podium only, no face)

## Unit tests

| Check | Result |
|---|---|
| `pytest tests/ -q` | PASS — 23 passed (13 kept from v0.1 + 10 new editing tests: crop geometry, face anchor math, edge clamping, center-crop equivalence, no-face/unopenable fallback) |

## End-to-end (real video, local file input, CLI)

### (a) Original 1080p, face track on — PASS

- `face_x=0.515` detected; crop 608x1080 at (684,0) from 1920x1080.
- Output 30.03 s, 1080x1920 H.264 + AAC, 89 caption events, MarginV 537 = (1-0.72)x1920.

### (b) Padded (off-center speaker), face track on — PASS

- `face_x=0.340` detected; crop 608x1080 at (676,0) from 2880x1080
  (center crop would be at 1136 — 460 px right, speaker out of frame).
- Output 30.03 s, 1080x1920, 89 caption events.
- Frame check (t=15 s): speaker centered in the 9:16 frame, caption
  "YEARS IS THAT" white with black outline, active word in gold.

### (c) Padded, `--no-face-track` control — PASS (demonstrates the v0.1 bug)

- Log: `center crop 608x1080 at (1136,0)` — the old behavior, reproducible on demand.
- Frame check (t=15 s): speaker's face half cut off at the left edge. This is
  exactly what v0.1 produced for off-center speakers and what (b) fixes.

### (d) Faceless variant, face track on — PASS (fallback)

- Log: `face found in 0/8 samples - center crop`; crop 304x540 at (808,0) from
  1920x540 (the v0.1 center position). Output 30.03 s, 1080x1920, 89 events.
- The 1-spurious-detection guard (MIN_FACE_SAMPLES=2) held: one false-positive
  frame during development did not move the anchor.

## AppImage — PASS

- Build: `./build-appimage.sh` (unchanged script, package paths renamed).
  Output `ShortsClipper-x86_64.AppImage`, 267,401,720 bytes (v0.1: 210,631,160;
  +57 MB is opencv-python-headless + numpy).
- Extracted `AppRun --cli` render of the padded input: face anchor 0.340
  (identical to the venv run), output 30.03 s, 1080x1920. Bundled Python 3.12,
  opencv, ffmpeg, and DejaVu font all work.
- GUI: extracted `AppRun` under `xvfb-run` launched and stayed up
  ("GUI started (drag-and-drop: on)"), killed by the tester after 25 s.

## What was NOT tested

- **YouTube URL input** — unchanged code path (transcript-first via official
  captions); datacenter IPs may get bot-checked (see README).
- **GUI drag interaction with a simulated mouse** — the drag handler is
  unchanged from v0.1; the crop it previews is now the face-anchored one
  (same `crop_box` the exporter uses, verified in unit tests).
- **Per-frame face tracking** — out of scope by design (one static median
  anchor per short; see README "Honest limits").
- **Windows / macOS** — Linux-only (AppImage, x86_64).
